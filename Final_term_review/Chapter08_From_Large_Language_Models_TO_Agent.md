# Chapter08: 从大模型到Agent

## 1.大模型的发展趋势: 从"会说"到"会做"
| 阶段        | 关键词                                                      |
| --------- | -------------------------------------------------------- |
| 2015–2020 | Transformer 架构演进、语料积累、CUDA 生态成熟                          |
| 2021–2024 | GPT-3 / ChatGPT 爆发、RLHF、百模大战                             |
| 2024–2025 | 迈向 Agent 时代，出现 Coze、Cursor、Microsoft 365 Copilot、Manus 等 |
| 2026      | 综合 Agent，从垂直 Agent 走向 All-in-one Agent                   |

```
从"高智低能"到"高智高能"
```


## 2. 什么是Agent?
### 2.1 强化学习语境下的Agent
```
Agent = 强化学习系统中的学习者 和 决策者
```
它的流程是
```
感知环境
-> 根据反馈规划下一步
-> 执行动作
-> 获得奖励或者惩罚
-> 调整策略
```

目标是:
```
找到最优策略、使长期累积奖励最大
```

### 2.2 大模型语境下的 AI agent

```
AI AGENT = 基于大模型构建的、能真正干活的智能助手
```

由三部分组成
```
AI agent = 大模型 + 工具 + 任务规划
```

| 组成   | 作用                      |
| ---- | ----------------------- |
| 大模型  | 大脑，负责理解、推理、规划           |
| 工具   | 手脚，负责搜索、计算、执行代码、操作软件    |
| 规划能力 | 决策系统，负责拆解任务、安排步骤、根据反馈调整 |

## 3. Agent的典型应用场景
ppt中的例子为:
```
发票整理
团建活动策划
购买推荐
程序编写
超级家教
写报告
```

这些场景的共同点是
```
不是指回复一句话，而是完成一个多步骤任务
```

## 4.大模型能力增强的四种方式

### 4.1 Prompt 提示词工程

| 技巧    | 含义              |
| ----- | --------------- |
| 角色扮演  | 让模型以某个身份回答      |
| 少样本提示 | 给几个例子，让模型模仿格式   |
| 思维链   | 引导模型分步骤思考       |
| 结构化输出 | 要求 JSON、表格、固定格式 |

### 4.2 RAG检索增强生成
RAG 可以比喻为
```
给模型一本参考书
```

流程
```
用户提问
-> 从外部知识库检索相关资料
-> 把资料和问题一起交给模型
-> 模型基于资料回答
```

适合
```
知识经常变化
需要引用外部文档
不想重新训练模型
```

### 4.3 Fine-tuning 微调
微调是
```
让模型专门去进修

它会用特定的数据继续训练模型、调整模型参数、使得模型更适合某个领域或者任务
```

适合
```
固定领域
固定任务格式
有足够高质量的训练数据
```

### 4.4 Tool Use 工具使用
Tool use是
```
让模型突破只能输出文本的限制，学会使用外部工具来完成任务
```
工具可以是
```
搜索引擎、计算器、代码执行环境、数据库查询接口、甚至其他AI模型
```

## 5. RAG \ Fine-tuning \ Tool Use的区分
| 方式          | 是否改模型参数 | 核心作用     | 类比    |
| ----------- | ------- | -------- | ----- |
| Prompt      | 否       | 改变提问方式   | 换一种问法 |
| RAG         | 否       | 增加外部知识   | 给参考书  |
| Fine-tuning | 是       | 改变模型能力倾向 | 专门进修  |
| Tool Use    | 否       | 增加执行能力   | 给手脚   |

## 6. Harness Engineering : Agent 外循环系统
它不是模型本身，而是让模型作为Agent 稳定工作的外部系统
包括
- 计划分解
- 持久状态
- 工具编排
- 验证门控
- 反馈回路
- 回退机制
- 人机交互设计
- 审计日志

## 7.MCP: 模型上下文协议

### 7.1 MCP解决什么问题
```
从 Function Calling 到 MCP 就是从各自为战到协同合作
```

MCP的目标是
```
用统一的接口连接模型、工具和数据源、应用
```

### 7.2 MCP的类比

```
MCP 就像是 AI 应用的 USB-C 接口
```

也就是
```
不同模型 / Agent
通过同一个标准接口
连接不同工具和数据源
```

### 7.3 MCP 的 三层结构
| 组件     | 含义     | 例子                          |
| ------ | ------ | --------------------------- |
| Host   | 宿主应用   | Claude Code、Trae 、Codex           |
| Client | 客户端调度层 | 负责和具体 MCP Server 通信         |
| Server | 服务端工具  | 百度地图、12306、本地文件、数据库、Web API |

流程可以记载为
```
用户提出任务
-> Host接受
-> Clinet 选择并连接MCP server
-> Server执行工具能力
-> 返回结果
-> 模型整理回答
```
## 8. MCPd的缺点: 上下文爆炸
```
MCP的问题是 每次对话都要把工具定义放进上下文
```
包括
- 工具名称
- 工具描述
- 参数
- 示例

PPT的例子是:
| MCP Server            |    工具数 |     约消耗 token |
| --------------------- | -----: | ------------: |
| 百度 Map server         | 10 个工具 |  约 2068 token |
| 12306 server          |  6 个工具 |  约 2068 token |
| GitHub MCP Server     | 27 个工具 | 约 18000 token |
| Playwright MCP Server | 21 个工具 | 约 13600 token |

## 9. Agent skills
### 9.1 Skill是什么
```
Agent skill = 给模型的操作手册
本质上是一个模块化的Markdown 文件
Skill.md
```
它告诉模型
```
在某个特定场景下，用什么步骤做事情，用哪些资源或者工具，输出什么格式
```
### 9.2 Skill的结构
| 部分           | 作用                  |
| ------------ | ------------------- |
| `SKILL.md`   | 技能说明、触发场景、执行规则、输出格式 |
| `reference/` | 参考文档                |
| `scripts/`   | 可执行脚本               |
| `assets/`    | 模板、资源文件             |

### 9.3 Skill的运行流程
```
用户请求
-> Trae 把请求和相关技能输入模型
-> 模型根据名称和描述选择技能
-> 加载此skill的 SKILL.md 和 reference
-> 按照skill.md的步骤执行，调用工具或者脚本
-> 返回结果
```
### 9.4 SKILL的优势 按需加载
| 机制    | 上下文占用                |
| ----- | -------------------- |
| MCP   | 往往一次性加载很多工具定义        |
| Skill | 先加载元信息，用到时再加载详细说明和资源 |

所以skill更适合
```
稳定流程
重复任务
本地文件处理
文档生成
论文总结
PPT 生成
```

## 10. 本章重点 MCP vs Skill
| 维度    | MCP                | Skill                  |
| ----- | ------------------ | ---------------------- |
| 本质    | 工具 / 数据源接入协议       | 任务执行说明书                |
| 解决问题  | 让模型连接外部工具和服务       | 告诉模型怎么稳定完成某类任务         |
| 类比    | Type-C / USB-C 接口  | 操作手册 / SOP             |
| 典型内容  | Server、工具定义、参数、API | SKILL.md、规则、格式、脚本、参考资料 |
| 上下文特点 | 工具多时容易上下文爆炸        | 按需加载，较节省上下文            |
| 适合场景  | 查地图、查票、连数据库、调 API  | 总结会议、处理文档、生成 PPT、科研助理  |

## 11. Skill Creator
Skill Creator 是用于自动创建 Skill 的工具。用户用自然语言描述需求，系统自动生成 Skill 文件结构、代码和测试用例，降低创建技能的门槛。
