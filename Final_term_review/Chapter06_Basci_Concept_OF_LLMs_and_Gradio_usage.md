# Chapter06 大语言模型浅析和Gradio使用

## 1.什么是LLM
### 1.1语言模型的本质

其实语言模型内部也就是一个巨大的神经网络，就是通过矩阵运算来处理文本数据的。

大语言模型不是像人一样理解问题，而是根据已经看到的上下文，预测下一个token的概率分布

### 1.2 “大” 体现在哪里

```
参数量大：通常有数十亿甚至数千亿的参数。
训练数据大：需要海量的文本数据来训练，以捕捉语言的复杂性和多样性。
计算资源大：训练和推理需要大量的计算资源，通常需要分布式计算。
```

## 2.LLM的训练过程

### 2.1 预训练
```
预训练阶段，模型在大规模文本数据上进行训练，学习语言的基本结构和规律。
```
训练方式
```
读大量文本，如百科全书、新闻、社交媒体等
通过预测下一个token来学习语言模式
```
### 2.2 监督微调 SFT
```
教模型如何按照人类希望的方式回答问题
```
训练数据通常是高质量问答对
```
用户问题 -> 理想回答
```

### 2.3 RLHF对齐
RLHF，即 Reinforcement Learning with Human Feedback，是一种通过人类反馈来优化模型行为的方法。

```
人类打分 -> 奖励模型 -> 强化学习优化语言模型
```

作用
```
让模型更符合人类的价值观和期望
减少有害或不适当的输出
```

### 2.4 领域微调 Domain SFT
```
针对特定领域进行微调，让模型在该领域表现更好
```

## 3.LLM的应用范围
```
文本生成：写作、对话系统、内容创作等
代码生成：自动编程、代码补全等
翻译：多语言翻译、跨语言信息检索等
总结：文档摘要、会议记录等
聊天机器人：客服、虚拟助手等
```

不擅长的
```
没有实时信息（除非联网）
幻觉
上下文长度有限
```

## Why Transformer


### 4.1 RNN / LSTM 的问题
```
按顺序处理
长句信息容易衰减
难以并行
速度较慢
```

### 4.2 Transformer的优势
注意力机制 
> 这就是大名鼎鼎的 《Attention is All You Need》 论文中提出的核心创新。

所有的token都可以直接访问输入序列中的所有其他token，这样就能捕捉长距离的依赖关系。

考试的话，就是
```
相比于RNN按照顺序处理，Transformer的注意力机制允许每个token直接访问输入序列中的所有其他token，从而更好地捕捉长距离依赖关系。
```

## 5. Transformer的三种结构

### 5.1 Encoder - Decoder

典型任务
```
机器翻译：输入是源语言文本，输出是目标语言文本。
文本 -> 文本
```

### 5.2 Encoder-only
BERT类模型

特点
```
双向编码：同时考虑上下文信息
适合理解和判别任务
```

### 5.3 Decoder-only
GPT类模型
特点
```
因果注意力
主看当前位置之前的token
适合生成任务
```

## 6. GPT/Decoder-only模型 介绍

```
1. 分词 ＆ 嵌入
2. 位置嵌入
3. 注意力层
4. 全连接层
5. 输出层
```

可以理解为
> 文字 -> token -> 向量 -> 加位置 -> 注意力融合上下文 -> FFN 处理 -> Softmax 预测下一个token

## 7. Tokenization分词
### 7.1 为什么要分词

计算机不能直接处理自然语言文字，所以要先把文本切成token，再转成token id

三种分词方式
```
1. 字符级分词：每个字符一个token
2. 单词级分词：每个单词一个token
3. 子词级分词：将单词拆成更小的单位，如BPE、WordPiece等
```
### 7.2 分词器的作用
分词器负责:
```
文本-> token -> token id
```

## 8. Embedding词嵌入
### 8.1 One-hot编码 的问题

例如词表
```
{ wish , you , a , good , day}
```
可以表示为
```
wish -> [1,0,0,0,0]
you -> [0,1,0,0,0]
a -> [0,0,1,0,0]
```

但是问题是
```
维度太高
非常稀疏
任意两个词距离相同，没有关联
无法表示语义关系
```

### 8.2 Embedding的作用

Embedding 把 token id 查表变成一个稠密的向量，通常维度在几十到几百之间。

例子
```
国王 - 男人 + 女人 = 女王
```

## 9. 位置编码
### 9.1 为什么需要位置编码
Transformer没有RNN那样的顺序处理机制，所以需要位置编码来告诉模型每个token在序列中的位置。

### 9.2 位置编码的方式
```
Embedding 告诉模型这个是什么词
Position Encoding 告诉模型这个词在句子中的位置
```

```
位置编码用于向 Transformer 注入 token 的顺序信息。因为自注意力机制本身不依赖递归或卷积，无法天然区分词序，所以需要将位置向量与词嵌入相加，使模型同时获得词义和位置信息。
```

## 10. Self-Attention机制
### 10.1 Q\K\V的定义

Embedding 加上位置编码之后，经过三次线性变换，得到 Query、Key、Value 三个矩阵。

| 矩阵 | 直觉               |
| -- | ---------------- |
| Q  | 当前 token 想找什么信息  |
| K  | 每个 token 能提供什么索引 |
| V  | 每个 token 实际携带的信息 |

### 10.2 Attention 公式
```
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```
含义
```
QK^T: 计算当前 token 与每个 token 的相关性
除以 sqrt(d_k): 缩放，防止数值过大
softmax: 转成概率分布，表示每个 token 的重要程度
乘以 V: 加权求和，得到融合了上下文信息的输出
```
### 10.3 Attention的效果
```
每个字对应的向量里面，都融入这句话中所有字的信息
```

## 11.Multi-Head Attention

```
一个注意力头关注一种关系
多个注意力头可以同时关注多种关系
```
例如
```
The animal did not cross the street because it was too tired.
```
模型需要判断it指代什么，那么不同的attention head 可能关注
```
指代关系
语法关系
语义关系
位置关系
```

## 12.注意力掩码 Mask

### 12.1 双向注意力
用于Encoder-only模型，如BERT，允许每个token同时关注前后所有token。

适合理解任务、判别任务

### 12.2 因果注意力
用于Decoder-only模型，如GPT，只允许每个token关注当前位置之前的token。

因为生成任务需要按照顺序预测下一个token

## 13.Layer Norm 和 Feed Forward Network
### 13.1 Layer Norm
Layer Norm 是一种归一化方法，作用是对每个样本的特征进行标准化，增强模型的训练稳定性和收敛速度。
```
训练稳定
收敛更快
不依赖batch size
适合变长序列
```

### 13.2 Feed Forward Network
FFN 是 Transformer 中每个注意力层后面跟着的一个全连接前馈网络，通常包含两个线性变换和一个非线性激活函数。
```
对每个token的表示进行独立的非线性变换
增强模型的表达能力
```
## 14. 输出层 Linear + Softmax
流程
```
隐藏状态 -> Linear 映射到词表大小 -> softmax -> 下一个token的概率分布
```

例子
```
输入: 我爱老
模型预测
师: 0.6
虎: 0.3
猫: 0.1
```

## 15.输出预测 Temperature, Top-k, Top-p
### 15.1 Temperature
```
控制生成文本的随机程度

低温度（<1）: 使分布更尖锐，更倾向于选择概率最高的token，生成更确定的文本。
高温度（>1）: 使分布更平坦，增加选择多样性的可能性，生成更有创意的文本。
```

### 15.2 Top-k
```
只考虑概率最高的k个token进行采样，其他token的概率设为0。
```
### 15.3 Top-p (Nucleus Sampling)
```
选择累计概率达到p的最小token集合进行采样，其他token的概率设为0。
```

## 16.Transformer的整体流程
```
文本
-> Tokenization
-> Token IDS
-> Embedding
-> Position Encoding
-> Self-Attention
-> Feed Forward Network
-> Linear
-> Softmax
-> 采样输出下一个token
```

```

```

## 19. Interface\Blocks\ChatInterface
### 19.1 Interface
适合简单的输入输出关系
```
核心参数:
fn: 定义输入输出关系的函数
inputs: 输入组件
outputs: 输出组件
examples: 示例输入
title: 应用标题
description: 应用描述
theme: 主题风格
```

### 19.2 ChatInterface
专门用于构建聊天界面，内置了对话历史管理和消息显示功能。
```
核心参数:
messages: 定义消息组件
history: 是否显示对话历史
```

### 19.3 Blocks
适合复杂的界面布局和交互逻辑，提供了更灵活的组件组合方式。
